# MSI MS-6117 (LX6)

This board uses Intel 440LX/PIIX4, Winbond W83977TF and an IMI SC643 clock
synthesizer. Optional clock programming and the portable SDR decoder are 
documented in [MS-6117 clock policy](ms6117-clock.md) and 
[SDR SPD support](../../memory/sdr-spd.md).

## OEM evidence

The routing for MS-6117 is derived from both AMI and Award $PIR templates and DSDTs:

* Award `611732x_patched.BIN`, SHA-256
  `46b0e42dda7bbde5a5d0dd57255d9d526653478a7d7f0ce528be0d52459f0822`.
* AMI `A617MS20.ROM`, SHA-256
  `787c30c6e1f7ff7536dba04da9106c60ae1579d3450905572025876858bb275e`.

| PCI 2       | 0x0f        | B    | C    | D    | A    |

| PCI 4       | 0x11        | D    | A    | B    | C    |

| AGP bridge  | 0x01        | A    | B    | C    | D    |
| PIIX4       | 0x07        | A    | B    | C    | D    |

PIIX4 USB uses INTD/PIRQD. The PM function uses independent SCI IRQ9.
Compatibility IDE remains on IRQ14/15. Devices behind bridges use PCI-core
interrupt swizzling before the root wiring is applied.

`routing.h` supplies the single compile-time wiring list for firmware IRQ
assignment, $PIR and ACPI. This is board wiring, not a southbridge-wide BDF
assumption. IRQ setup runs after device initialization and verifies the PIIX4
router and programmed routing bytes.

AMI's 144-byte $PIR template is at `amibody_02.rom+0x0db0`; Award's is at
`original.tmp+0x1de60`. Both have unset runtime checksums. Award also has a
stale router device ID 0x7000. Coreboot tables use the real PIIX4
ID 0x7110 and calculate their checksum from fully initialized contents.

## Interrupt policy

`CONFIG_MS6117_PCI_IRQ_MASK` defaults to 0x0c00 (IRQ10/11). The nonempty pool
may contain only IRQ5/10/11. Default assignments are A=10, B=11, C=10, D=11.
This is coreboot policy, not an OEM fixed assignment.

IRQ5 is excluded by default for ISA audio. Add it only when no ISA card uses
it. Remove IRQ10/11 if a non-PnP ISA card needs either. UART, floppy, parallel,
mouse, IDE and SCI IRQs are never added to the selectable PCI pool.

ACPI _PRS and $PIR advertise the same pool. Link _SRS accepts a single IRQ
from that pool and updates ELCR level triggering. Disabled links report an
empty _CRS IRQ bitmap. Firmware uses the standard PIC trigger helper, not a
late blanket ELCR reset. The generic PIRQ link-index routing engine is not
used: PIIX $PIR links are offsets 0x60-0x63, not indices 1-4.

## ACPI and resources

Both OEM DSDTs are revision1 and advertise S0/S1/S5. Their S1 paths depend on
vendor SMI/device-trap behavior. Coreboot advertises only S0/S5 until a real
resume path is validated; it does not copy fan/LED GPIO sleep operations.
Shared ACPI code remains unchanged and uses its existing revision2 DSDT.
There is no complete Windows98 ACPI compatibility.

SCI is IRQ9 in both OEM implementations. Award uses PM/SMBus bases
0x4000/0x5000 and ACPI enable/disable commands A1/A0. AMI uses 0x6100/0x5f00
and E1/1E. Coreboot retains its own PM/SMBus bases 0xe400/0x0f00; FADT and
resource reservations must describe those actual decodes. Its optional SMM
handler uses E1/1E, so we are not substituting Award's command bytes as these
would be wrong.

Additional legacy reservations include timer aliases0x44-0x5f,
Super I/O configuration0x3f0-0x3f1, ELCR0x4d0-0x4d1 and0x295-0x296.
The latter reservation does not establish a hardware-monitor programming
interface. APMC B2/B3 is already inside the reserved PIC alias rangeA2-BF.

AMI early DRB values0x10 in all rows are temporary sizing mappings, not final
installed capacity. Timing, geometry and buffer strength must follow actual
DIMMs and current errata policy.

Award's traced SMRAM0x4a-to0x0a transition clears D_OPEN after
copying an ASEG handler; it does not justify opening SMRAM during PCI/VGA
operation in our current coreboot implementation.

The optional ASEG SMM implementation remains experimental and implements
APMC/ACPI handoff only. USB legacy SMM emulation and S1/S3 resume are not
implemented.

## SMBIOS

The port supplies Type9 entries for five PCI slots, AGP and two ISA slots.
AGP occupancy and its endpoint address come from an enabled child device;
the root bridge itself is not mistaken for an installed card. ISA occupancy
and its PCI address are unknown. Slot voltage/length characteristics are
not implemented. Serial ports are identified as16550A compatible, USB ports
are not labeled USB2.0, and the floppy port is not labeled an8251 UART anymore.

OEM DMI CPU, memory and version records are templates. AMI even carries
stale BIOS date/version defaults. Future Type16/17 inventory must use final
RAM initialization results and actual SPD identity. SMBIOS inventory is
not a substitute for PCI/ACPI/PnP device enumeration or OS drivers.

## Validation still required

Host-toolchain ROM links, AML compilation and ACPICA simulated-region tests.
Test all physical PCI slots, AGP/bridge swizzling, shared USB interrupts, 
ISA resources, runtime table checksums, SCI event handling and shutdown 
on hardware. 

Final ROM allocation must be checked with the actual SeaBIOS/microcode/NVRAMCUI 
selection.

Windows98 compatibility additionally needs a deliberate ACPI table/version
and payload interface review, appropriate chipset drivers and runtime device
resource tests. S1/S3, GPIO wiring, LPT ECP DMA encoding and SC643 clock
programming require separate work.
